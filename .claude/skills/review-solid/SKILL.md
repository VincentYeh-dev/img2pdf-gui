你將對 img2pdf-gui 專案進行 **SOLID 原則** 的唯讀審查。

**嚴格禁止**：不得使用 Edit、Write、Bash 工具，不得修改任何檔案。

---

## 評估態度

不直接判斷「是否違反」，而是判斷「違反是否值得重構」。審查時需考量：
- 違反程度是否實際造成維護困難或擴充阻礙？
- 重構所需成本（涉及幾個檔案、幾行）是否值得投入？
- 若屬輕微違反但整體可讀性良好，可評為「可接受的 trade-off」並說明理由，不必強制列為問題。

---

## 檢查點

- **SRP**：每個類別是否只有一個職責？若職責混合，是否已造成維護問題？
- **OCP**：新增 UI 元件或排序方式時，是否需要修改既有邏輯？修改成本如何？
- **LSP**：介面實作（`ModelListener`、`MediatorListener`）是否完整且語意正確？
- **ISP**：介面方法是否所有實作者都需要？若有胖介面，拆分成本是否值得？
- **DIP**：高層模組（Controller）是否依賴抽象介面而非具體實作？

---

## 輸出格式

以 Markdown 呈現，每個問題使用以下模板：

```
### [SOLID] 問題標題

- **位置**：`檔案路徑:行號`
- **問題**：具體描述問題是什麼
- **建議方向**：改善方向（不提供修改後的程式碼）
- **嚴重度**：高 / 中 / 低
- **重構必要性**：必要 / 建議 / 可選（附理由）
- **重構成本估算**：涉及 N 個檔案，約 N 行需更動（必要或建議時填寫）
```

**若發現需要關注的違反，必須填寫「重構必要性」與「重構成本估算」欄位。**

節末提供**小結**，列出此面向的整體評估（良好 / 待改善 / 需重構）。

## 絕對限制

- **只讀不改**：本技能為純審查，禁止提出具體程式碼修改。
- **不猜測程式行為**：有疑問時以 Grep 搜尋確認，不憑印象判斷。
